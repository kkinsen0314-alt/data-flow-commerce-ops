# Data Flow 数据源接入规范 v1

## 当前已连接数据源

当前正式后台只登记一个已连接数据源：电商运营测试数据。其接入类型为本地文件（CSV），包含短视频、直播场次、渠道线索、销售跟进和订单五个数据集，共 89 条记录。后台运行时读取 `data/fixtures/period-13/` 下的五份 CSV；XLSX 仅作为人工查看副本，不是运行时数据源。

MySQL、PostgreSQL、飞书、HTTP API 和 MCP 当前均未配置为已连接数据源。界面中的“可接入”仅表示平台支持该接入方向，不表示已经取得账号、权限或业务数据。

## 接入类型

| 类型 | 连接方式 | 默认权限 | 当前状态 |
|---|---|---|---|
| CSV / Excel | 本地受控文件 | 只读 | 已启用 |
| MySQL | 数据库连接器或受控 MCP Server | 只读账号、限定库表/视图 | 可配置 |
| PostgreSQL | 数据库连接器或受控 MCP Server | 只读账号、限定库表/视图 | 可配置 |
| 飞书多维表格 | 飞书 OpenAPI，经 MiniClaw MCP 能力注入 | 仅读取指定应用与数据表 | 可配置 |
| 飞书电子表格 | 飞书 OpenAPI，经 MiniClaw MCP 能力注入 | 仅读取指定表格与工作表 | 可配置 |
| HTTP API | 受控 HTTPS 客户端 | 仅允许登记过的域名和路径 | 可配置 |
| MCP 连接器 | MiniClaw MCP Server | 仅启用登记过的只读工具 | 可配置 |

## MiniClaw 与飞书的边界

MiniClaw 的飞书消息渠道负责接收消息、读取会话上下文和发送回复或卡片。飞书多维表格、电子表格等业务数据应作为独立数据连接器接入，不应把消息渠道等同于业务数据源。

网页端发起的分析不依赖飞书消息上下文。正式飞书数据连接器应使用独立飞书应用凭据和最小权限，通过 MiniClaw 的 MCP、插件、密钥和能力注入机制暴露只读数据工具，再将读取结果转换为统一的数据集清单后交给专业 Agent。

## 正式接入要求

1. 凭据只保存在服务端，浏览器只显示脱敏连接状态。
2. 数据库必须使用只读账号，限定数据库、表或视图，并设置查询超时和最大行数。
3. 飞书应用只申请目标多维表格或电子表格所需的读取权限，并记录应用、数据表和字段映射。
4. HTTP API 必须限制域名、路径、方法和返回体大小。
5. MCP 只启用登记过的 Server 和工具；通用写入工具不得进入数据分析 Workspace。
6. 外部数据先生成不可变分析快照和数据质量清单，Agent 不直接执行任意 SQL 或任意 OpenAPI 请求。
7. “已连接”只能由成功的凭据校验、权限校验和最小读取测试产生，未配置项不得显示为可用数据源。

## 下一接入门槛

实际接入 MySQL 需要数据库地址、端口、库名、只读账号、允许读取的表或视图，以及字段到 Data Flow 数据集契约的映射。实际接入飞书需要 App ID、App Secret、管理员批准的读取权限、目标表格标识及字段映射。凭据应通过本机管理员配置或环境变量录入，不应写入仓库、测试夹具或浏览器存储。
