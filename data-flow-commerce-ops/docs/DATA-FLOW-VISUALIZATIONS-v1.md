# Data Flow 数据看板

> 2026-09-24：实现、接口回归和完整浏览器验收均已完成。隔离验收 8/8 通过，Python 全量回归 127/127 通过，真实模型调用与模拟分析提交均为 0。

## 入口与范围

启动原有 `scripts/start-native-runtime.ps1` 后，使用 MiniClaw 账号登录，在运营工作区选择“数据看板”，或打开 `http://127.0.0.1:3017/operations/visualizations`。

本小节交付确定性经营看板：五个核心指标、六组图表、日期/渠道/内容/直播场次筛选、脱敏明细分页、PNG 图片与筛选后 CSV 导出。看板不创建分析任务或模型会话。自由对话和对话联动图表属于后续小节；飞书、MySQL 等外部连接仍沿用既有接入规划。

当前唯一数据源是第 13 期合成测试 CSV 文件集。页面保留“合成测试数据”标识，主界面不出现内部阶段或评测状态。五类共 89 条记录：18 条内容、24 条用户×直播场次、18 条线索、17 条跟进、12 条订单；直播为 2 个场次、18 个去重用户。

## 指标与筛选口径

| 指标 | 全量基准 | 计算方式 |
|---|---:|---|
| 有效付款金额 | ¥10,591 | `paid`、`completed` 订单金额之和 |
| 有效付款订单 | 9 | 付款有效订单按订单编号去重 |
| 线索数量 | 18 | 按线索编号去重，包含无效及无跟进线索 |
| 付款转化率 | 50% | 有付款订单的去重线索 / 全部筛选线索 |
| 24 小时首跟进率 | 72.2222% | 首跟进距分配时间 0–24 小时的线索 / 全部筛选线索 |

- 开始、结束日期均包含当天，依据线索创建时间。默认覆盖 2026-08-31 至 2026-09-05 的线索；后续数据观察至 2026-09-06 22:30。
- 跟进、直播行为和订单属于所选线索的后续记录，不用线索创建日期截断付款日期。例如只选 8 月 31 日仍包含 9 月 1 日支付的 ¥899。
- 渠道、内容、场次和日期取交集。场次通过用户编号关联线索，订单再通过线索编号关联，不表示直播促成订单，也不重复累加同一用户跨场次的订单。
- 内容曝光与点击是关联内容的完整次数，不是所选渠道独占流量；曝光、点击、线索为不同粒度，路径图展示规模，不能当作用户级漏斗转化率。
- 直播只提供预约时间，无真实开播时间。按场次比较预约、到课和购买行为，不捏造开播日期趋势。直播购买标记与订单有效付款是两个口径。
- 无首跟进的线索留在分母并单独分组；时间异常单独展示。分母为零时转化率返回 `null`，界面显示“—”。待付款、取消订单仍可查看，金额贡献为零。

## 实现与接口

`commerce_ops/visualizations.py` 只读加载服务端允许的数据文件，检查必要字段和稳定主键；完全重复记录去重，冲突主键拒绝。数据快照每次从当前文件计算，不从模型回复提取数值。

| 接口 | 用途 |
|---|---|
| `GET /v1/operations/visualizations` | 核心指标、图表、筛选选项和数据口径 |
| `GET /v1/operations/visualizations/details/{dataset}` | 脱敏明细；支持 `offset`、`limit`，单页上限 100 |
| `GET /v1/operations/visualizations/export/{dataset}.csv` | 导出全部筛选明细，UTF-8 BOM，文本防公式注入 |

通用参数：`source_id`、`date_from`、`date_to`、`channel`、`content`、`session`。明细类型为 `content`、`live`、`leads`、`followups`、`orders`；前端分页每页 20 条。调用方不能指定文件路径、SQL 或第三方地址。

三个接口复用 MiniClaw 当前账号和工作区授权、精确来源限制及 `no-store` 响应。权限拒绝和登录过期时界面清除可见图表；筛选失败不保留一组与当前条件不匹配的图表。

前端使用项目已有 Recharts 依赖、按路由延迟加载，复用认证请求层。PNG 从当前 SVG 图表生成，包含来源、合成属性、筛选范围和统计说明；CSV 与明细使用相同计算逻辑。前端和构建产物均位于 project017，上游 MiniClaw 源码保持只读。

未来外部数据接入应先归一化为相同的内容、线索、跟进、直播参与、订单实体，再注册服务端数据源；不能只增加下拉选项就视为完成连接。

## 验证

新增 `tests/test_visualizations.py` 覆盖 9 个场景，包含金额口径、日期边界、交集、零分母、分页、导出一致性、认证、坏输入和数据源失败；连同既有回归共 127 项通过。

`tests/operations_browser_harness.py` 提供隔离的身份和模型测试替身，业务看板接口与数据计算使用正式实现；`tests/verify_data_flow_visualizations.mjs` 验证桌面/手机布局、下载、筛选、分页与权限。运行前须确认 3017/3022 没有正式服务；测试代码会核验专用夹具标记。该验收不会提交模型任务，也不代表新增真实 Provider 评测。

浏览器工具在当前 Windows 版本下的下载命令会向 Chrome 传入扩展路径，最小 Blob 下载同样失败。测试仅通过该命名浏览器自身的 CDP 设置普通绝对下载路径，然后点击真实产品按钮，等待下载完成，验证文件内容；不修改系统策略或产品下载实现。

同一版本的 `agent-browser fill` 与键盘输入不能给 Chrome 原生日期控件写值。浏览器验收通过原生 value setter 写入控件并派发 `input/change` 事件，回读 React 受控值后点击页面的“应用筛选”，最终核对后端结果。该兼容处理只在验收脚本中，正式前端仍使用浏览器原生日期控件。
